# ETF Daily Master V2 rebuild

## Colab execution
1. Mount Google Drive: from google.colab import drive; drive.mount('/content/drive')
2. Clone this branch and install dependencies: `pip install -r requirements-etf-data-pipeline.txt`.
3. Put KR_ETF_Universe.xlsx and US_ETF_Universe.xlsx under MyDrive/ETF_Data/input/.
4. Run rebuild_etf_master_v2.py in Colab.
5. Outputs are written only to MyDrive/ETF_Data/rebuild_v2/. Existing V1 files are not deleted or overwritten.

## Safety and outputs
- Synthetic/mock data fallback is prohibited.
- Preserves OHLC, adjusted close, volume and estimated turnover.
- Corporate actions reported by provider are stored separately.
- Failed downloads are logged; a failure is not automatically labelled as delisting.
- Batch Parquet checkpoints and status CSVs support resuming after Colab disconnects.
- Final outputs: ETF_Daily_Master_v2.parquet, ETF_Corporate_Actions_v2.parquet, ETF_Daily_Master_v2.xlsx, status/failure/quality CSVs, run_manifest.json.
- Excel is one workbook, with price data split across year/market/part sheets to respect sheet row limits.
- turnover_estimated = close * volume is an estimate, not official exchange turnover.
- Yahoo Finance is a third-party source. History coverage and corporate-action adjustment conventions must be validated.
- If universe files contain only currently listed ETFs, survivorship bias remains; historical/delisted ETF universe data is a separate required source.
- NAV, AUM, fees, holdings, benchmark constituents, FX, rates and investor flows are not generated by this price collector. They should be added as separately sourced datasets, never filled with invented values.
- Test a small sample before full-universe historical collection.

## Required validation after collection

Collection success is not quality approval. Run `run_quality_pipeline.py` with an independently sourced calendar whose rows include `calendar_verified=true` and `calendar_source`. Review every `BLOCKED`/`CONDITIONAL` ticker before any Alpha V1 use.

If verified repair evidence is later supplied, run `run_repair_pipeline.py` to a new candidate path, then `validate_repair_pipeline.py`. Build the free-account handoff last with `build_handoff_package.py`. Full instructions are in `docs/ETF_DATA_PIPELINE_RUNBOOK_KR.md`.
